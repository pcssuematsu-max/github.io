## プロダクトの目的

portfolio、キューブ教材、AI探索結果の表示に共通利用できる自前の3Dパズルビューアを作る。最初は3×3を「触って気持ちよく、手順を迷わず追える教材」として完成させ、その後NxN、異形パズルに広げる。

最上位の判断基準は、利用者が「いまどの手を実行しているか」を常に追えること。見た目・視点・操作・再生UIはいずれもこの体験を優先する。

## 守る設計原則

- 論理状態の遷移、3D描画、回転アニメーションを別の責務にする。
- UIテーマと、各面キャップの色・内部機構の色の設定を混ぜない。
- 3×3固有の条件分岐を増やさず、`PuzzleDefinition` を追加して対応パズルを広げる。
- PCとスマホを同じ製品として扱い、レスポンシブ表示とタッチ操作を初期設計に含める。
- 既存の `cubing.js` 再生ページは外部ライブラリを使う公開機能として維持する。独自ビューアは教材表現・色設定・将来の共通利用を担う別コンポーネントにする。

## Phase 1の完了条件（3×3最小版）

1. 3×3を描画し、ドラッグで360度見回せる。正面へ戻す操作を持つ。
2. `R` / `U` / `F` とその派生手を、ボタンと手順文字列から実行できる。
3. 再生・停止・一手送り・一手戻し・先頭へ戻す・速度変更を提供する。
4. 手順列の現在手を強調し、完了済みの手を淡色化する。`現在手数 / 総手数` を常時表示する。
5. 回転は0°から90°へ滑らかに見せ、アニメーション完了後に論理状態を確定する。
6. 既存portfolioのUIに馴染むテーマ、面キャップ配色、内部機構の色を分離して設定できる。

背景ドラッグによる視点回転は有効にする。ステッカー上のスワイプによる面回転は一時停止する。現行の「触れた面そのものを回す」判定は、FRUコーナーのF面を上へ動かしたときにR面が回る期待に一致しない。面・ドラッグ方向・回転対象層の対応を再設計してから再開する。再開時は、直接回転の1手を再生履歴へ追加して一手戻し・共有URLと同じ状態モデルで扱う。

## 最初のアーキテクチャ境界

```text
Viewer API（外部ページから渡す: puzzle / initial state / algorithm / theme）
        │
        ├─ Playback controller     再生位置、速度、前後移動、進行表示
        ├─ Puzzle state engine     手の解釈、状態遷移、履歴
        ├─ Animation coordinator   回転対象、補間、確定タイミング
        ├─ Renderer                シーン、カメラ、ピース、ステッカー
        └─ PuzzleDefinition        形状、面、軸、手、ピース、寸法
```

### `PuzzleDefinition` の必須データ

- `pieces`: ピースID、位置、向き、ステッカー
- `faces`: 面の名前・法線・表示上の対応
- `axes`: 回転軸
- `moves`: 対象ピース、回転軸、角度、状態遷移
- `geometry`: 形状、ピース寸法、列幅、丸みなど

Phase 1の実装は3×3用の定義をひとつ用意する。ただし状態エンジンと描画側は「3×3だから」という分岐を持たず、この定義を入力として扱う。

## 将来要件の記録

- NxNでは、特に4×4以上で外側列を内側列より太くし、列幅を`geometry`で指定できるようにする。比率は`Rubiks_portfolio/core/cube_constants.py`の`inside_size`と`outside_size`を正本とし、表示サイズへ正規化して使う。
- 面キャップと内部機構は`#RRGGBB`で設定可能にする。
- 3×3の基準造形は、中国製ステッカーレスキューブらしい印象を目標にする。各キュービーは、面ごとに色を変えられる丸い樹脂シェルとして表現する。直線状のパネル辺（A）と面外周の角（C）は控えめに丸め、面内の格子点に接するパネル角（B）だけは大きく丸める。これにより、各面の中央は平らに保ちながら、隣り合う丸い四隅がつくる小さな星形の抜けを表現する。キュービー同士はほぼ接する細い隙間に抑え、中性の内部機構はその隙間からだけ見せる。太い黒枠や色付きの縁、センターキャップのロゴは使わない。A・B・Cと隙間の比率は、実機写真と見比べて個別に調整可能にする。
- 教材用に特定ステッカーを物理ステッカーID（`pieceId:face`）で指定し、手順中も追従させる。指定色と非注目ステッカー色はページごとのテーマとして渡す。既存Web教材のF2L配色（水色＝クロス色、ピンク＝手前、黄緑＝横、グレー＝今回追わないパーツ）は設定可能性を示す試作であり、F2Lを独自ビューアへ載せ替える段階で、ケースごとの開始状態・注目ステッカー・配色を改めて組み直す。
- 背景ドラッグによる視点回転は有効に保つ。ステッカー上のスワイプ回転だけは、面・ドラッグ方向・回転対象層の対応を再設計するまで無効化する。FRUコーナーのF面を上へ動かしたときにR面が回るような、物理的に直感的な層選択を再開条件とする。
- 公式対象は2×2〜7×7、Megaminx、Pyraminx、Master Pyraminx、Skewb、FTO、CTO。GigaminxとSquare-1は後から検討する。
