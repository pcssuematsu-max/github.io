# 3Dパズルビューア｜Phase 1 UIと3×3定義

> 関連する技術設計: [3d-puzzle-viewer-phase-1.md](3d-puzzle-viewer-phase-1.md)
>
> 決定日: 2026-09-15

## UIの優先順位

最上位UX目標である「いまどの手を実行しているか」を守るため、画面の優先順位を次の順にする。

1. 立体表示と現在手
2. 再生・前後移動・進捗
3. 手順の入力と編集
4. 視点リセットと速度
5. 色設定などの表示調整

背景をドラッグすると視点を回転できる。ステッカー上のスワイプによる面回転だけは一時停止する。現行の「触れた面そのものを回す」判定では、FRUコーナーのF面を上へ動かしたときにR面を回したい期待に応えられないためである。面・ドラッグ方向・回転対象層の対応を組み直してから再開する。

## PCの画面構成

```text
┌──────────────────────────── 3D Puzzle Viewer ────────────────────────────┐
│  [3×3]  [視点を正面へ]                                  [配色 ▾]        │
├───────────────────────────────┬──────────────────────────────────────────┤
│                               │  手順                                    │
│                               │  [ R U R' U'                         ]    │
│           3D Canvas           │  [表示する]                              │
│ 背景ドラッグ: 視点回転         │                                          │
│     ピンチ / ホイール: 拡大    │  現在:  3 / 4                           │
│                               │  R   U   R'  U'                          │
│                               │          └─ 現在手を強調                 │
│                               │                                          │
│                               │  [最初へ] [戻る] [再生 / 停止] [進む]    │
│                               │  速度: [0.5×] [1×] [1.5×]                │
└───────────────────────────────┴──────────────────────────────────────────┘
```

- Canvasは横幅の約60%、最小高さ440pxを確保する。右パネルが狭くなっても、現在手と再生ボタンを切り離さない。
- 画面タイトル横の`3×3`は、将来のパズル選択の位置を予約する。Phase 1では固定表示でよい。
- 手順トークンはクリックしてその手へ移動できる。完了済みは淡色、現在手はテーマのアクセント色、未実行は通常色で表示する。
- `再生`は再生中に`停止`へ表示を切り替える。ただし停止要求は現在の一手のアニメーションが終わったあとに反映する。
- 配色は折りたたみパネルに置く。再生操作の近くへ常時展開しない。

```text
┌──────────────────────────────┐
│ [3×3]          [正面へ戻す]  │
│                              │
│          3D Canvas           │
│ 背景ドラッグで視点を回転      │
│                              │
├──────────────────────────────┤
│ 現在: 3 / 4                  │
│ R    U    R'    U'            │
│          └─ 現在手            │
│ [最初へ] [戻る] [再生] [進む]│
│ 速度: 0.5×  1×  1.5×         │
├──────────────────────────────┤
│ 手順を編集 ▾                  │
│ 配色を調整 ▾                  │
└──────────────────────────────┘
```

- Canvasは幅いっぱい、最小高さ300px。操作UIより先に立体と現在手を見せる。
- 編集フォームと配色はアコーディオンにし、再生中にUIが縦へ伸びないようにする。
- 再生・一手戻し・一手送りは常時見える大きさにする。タップ領域は最低44px角。
- 背景ドラッグとピンチ操作で視点を調整できる。ステッカー上のスワイプ回転は一時停止し、再開時は背景の視点変更と競合せず、期待する隣接層を選べる規約を採用する。

## アクセシビリティと入力規約

- Canvasの外に、現在状態を文章で示すライブ領域を置く。例: `3手目 / 4手中。現在の手は R'。`
- 全機能にラベル付きボタンを持たせ、アイコンだけにしない。
- キーボード操作は`Space`で再生・停止、`←`で戻る、`→`で進む。ただし手順入力欄にフォーカス中は奪わない。
- `prefers-reduced-motion: reduce`ではアニメーション時間をほぼ0にしつつ、状態の移り変わりと現在手の強調は残す。
- WebGL 2が使えない場合は、手順と現在位置を操作できるテキストUIを残し、3D部分には理由と対応環境を表示する。

## 3×3の座標規約

論理状態と描画で、同じ右手座標系を使う。

```text
      +Y = U
       ↑
       │
       └──→ +X = R
      ／
 +Z = F
```

| 軸の値 | 対応する外面 | 層の意味 |
| --- | --- | --- |
| `x = +1` / `-1` | `R` / `L` | 右 / 左 |
| `y = +1` / `-1` | `U` / `D` | 上 / 下 |
| `z = +1` / `-1` | `F` / `B` | 前 / 後 |
| `0` | 外面なし | 中間層 |

slotは`[-1, 0, 1]³`から`[0, 0, 0]`を除いた26個。IDは、その座標にある外面を`U, D, F, B, R, L`の順で連結する。

```js
function cube3SlotId([x, y, z]) {
  const names = [];
  if (y === 1) names.push("U");
  if (y === -1) names.push("D");
  if (z === 1) names.push("F");
  if (z === -1) names.push("B");
  if (x === 1) names.push("R");
  if (x === -1) names.push("L");
  return `slot-${names.join("")}`;
}

// 例: [ 1, 1, 1] → slot-UFR
//     [ 0, 1, 1] → slot-UF
//     [ 1, 0, 0] → slot-R
```

ピースのIDは解法時のslot名を使う。よって、解法状態は全ピースが同名のhome slotにあり、`orientationId: "identity"`となる。

```js
{
  id: "corner-UFR",
  homeSlotId: "slot-UFR",
  stickers: { U: "U", F: "F", R: "R" },
}
```

## 26ピースを生成する定義

3×3専用のピース一覧を手書きしない。次の規約で実データを生成し、結果を`PuzzleDefinition`に固定する。

```js
const indices = [-1, 0, 1];

function createCube3Pieces() {
  return indices.flatMap((x) => indices.flatMap((y) => indices.flatMap((z) => {
    if (x === 0 && y === 0 && z === 0) return [];
    const slotId = cube3SlotId([x, y, z]);
    const stickers = Object.fromEntries([
      y === 1 && ["U", "U"], y === -1 && ["D", "D"],
      z === 1 && ["F", "F"], z === -1 && ["B", "B"],
      x === 1 && ["R", "R"], x === -1 && ["L", "L"],
    ].filter(Boolean));

    return [{
      id: `${Object.keys(stickers).length === 3 ? "corner" :
             Object.keys(stickers).length === 2 ? "edge" : "center"}-${slotId.slice(5)}`,
      homeSlotId: slotId,
      stickers,
    }];
  })));
}
```

生成結果はcorner 8、edge 12、center 6、合計26件でなければエラーにする。これが最初の`compileDefinition()`検証である。

## 3×3の面回転を定義する規約

すべての基本手は「その面を外側から見て時計回り」を正方向とする。座標上の回転は、外向き法線のまわりに`-90°`と定義する。逆手は`+90°`、2回転は`-180°`を使う。

| 手 | 対象slot | 外向き法線 | 正方向の角度 |
| --- | --- | --- | --- |
| `U` | `y = +1` | `[0, 1, 0]` | `-90°` |
| `D` | `y = -1` | `[0, -1, 0]` | `-90°` |
| `R` | `x = +1` | `[1, 0, 0]` | `-90°` |
| `L` | `x = -1` | `[-1, 0, 0]` | `-90°` |
| `F` | `z = +1` | `[0, 0, 1]` | `-90°` |
| `B` | `z = -1` | `[0, 0, -1]` | `-90°` |

```js
const cube3BaseMoves = {
  U: { selector: { axis: "y", value: 1 }, rotation: { axis: [0, 1, 0], degrees: -90 } },
  D: { selector: { axis: "y", value: -1 }, rotation: { axis: [0, -1, 0], degrees: -90 } },
  R: { selector: { axis: "x", value: 1 }, rotation: { axis: [1, 0, 0], degrees: -90 } },
  L: { selector: { axis: "x", value: -1 }, rotation: { axis: [-1, 0, 0], degrees: -90 } },
  F: { selector: { axis: "z", value: 1 }, rotation: { axis: [0, 0, 1], degrees: -90 } },
  B: { selector: { axis: "z", value: -1 }, rotation: { axis: [0, 0, -1], degrees: -90 } },
};
```

`compileDefinition()`は各回転を座標へ適用し、対応するslotを探索して`slotMap`を生成する。ここで対象slotが9個、mapが全単射で、基本手を4回適用するとidentityになることを検証する。向きも同じ回転から生成するため、手書きの置換表と描画アニメーションの向きが食い違わない。

## 3×3の拡張表記

3×3では外層だけでなく、中央層・2層wide・全体回転も同じ「対象層 + 回転軸 + 角度」の定義で扱う。中央層の標準方向は`M = L`、`E = D`、`S = F`とする。

| 表記 | 同じ状態になる展開 |
| --- | --- |
| `Rw` / `r` | `R M'` |
| `Lw` / `l` | `L M` |
| `Uw` / `u` | `U E'` |
| `Dw` / `d` | `D E` |
| `Fw` / `f` | `F S` |
| `Bw` / `b` | `B S'` |
| `x` | `R L' M'` |
| `y` | `U D' E'` |
| `z` | `F B' S` |

対応する各手は、逆手と4回転で解法状態へ戻ることを自動テストする。画面では、複数層にまたがる手でも該当ピースをひとつの一時グループへ集め、1回のアニメーションとして回転させる。

## 最小デモの受入条件

次の実装段階では、新しい専用ページ上で以下を満たすことを受入条件にする。

1. 解法状態の3×3を、マウスとタッチで360度見回せる。視点リセットで基準視点へ戻せる。
2. `R U R' U'`を入力し、現在手を強調しながら前後・自動再生できる。
3. `R`、`R'`、`R2`を含む任意の外層手が、論理状態と同じ向きにアニメーションする。
4. 視点リセット、速度、配色プリセット、特定ステッカーのグレー化が動く。
5. PCと幅320pxのモバイル画面で、現在手と再生・前後移動が常時見える。
